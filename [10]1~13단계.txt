1단계: 내부 명령 수신 및 검증

STM32로부터 내부 명령 프레임 수신 (구분자/CRC로 프레임 완결성 확인)
필드 파싱: FTP타입, IP/Domain, Port, 경로, ID, PWD, 통신서버IP (모두 STM32가 복호화한 평문)
필드 유효성 검사 (Port 숫자 범위, IP 형식, 공백 트림 등)
검증 실패 시 → STM32에 "파라미터 오류" 응답 후 종료

2단계: MCU에 수신 확인 응답

"명령 정상 수신, 다운로드 시작함" ACK를 시리얼로 회신
이 시점부터 STM32는 대기 상태 (RPi가 진행 주체)

3단계: 사전 점검

저장 공간 확인 (다운로드 파일 + 기존 백업 보관 여유)
임시 디렉토리 준비, 이전 실패 잔여 파일 정리
네트워크 도달성 확인 (VPN 경유 SFTP 서버 ping 또는 TCP 연결 시도)

4단계: SFTP 접속

paramiko로 접속 (IP/Domain + Port + ID + PWD)
접속 타임아웃 설정 (예: 30초), 실패 시 재시도 정책 적용 (예: 1회)
최종 실패 시 → STM32에 "접속 실패" 결과 보고 후 종료

5단계: 파일 다운로드

전달받은 경로에서 파일 다운로드 (규격상 압축된 단일 파일)
임시 파일명으로 저장 (예: firmware_new.zip.tmp) — 완료 전 정식 파일명 사용 금지
다운로드 타임아웃/전송 중단 감지
완료 즉시 SFTP 세션 종료 (규격 SFTP 접속절차 (4)항: 다운로드 완료 시 접속 종료)

6단계: 파일 무결성 검증

파일 크기 0 여부, 압축 해제 성공 여부 확인
압축 내 hex 파일 존재 및 형식 검증 (Intel HEX 라인 체크섬 검사 — 각 라인 파싱해서 검증 가능)
검증 통과 시 정식 파일명으로 rename (원자적 완료 처리)

7단계: MCU에 다운로드 결과 보고

성공: "다운로드 완료, 플래싱 대기 중" + 파일 크기/해쉬 등 부가정보
실패: 실패 사유 코드 (접속 실패 / 다운로드 중단 / 파일 손상 등)
이후 플래싱 진행 여부의 최종 판단은 다시 STM32에게 넘어감

8단계: 플래싱 준비 (부트로더 진입)

STM32로부터 "플래싱 승인" 명령 수신
시리얼 브리지 동작 중지 — 이 순간부터 UART는 stm32flash 전용 (평소 브리지 프로세스가 포트를 점유 중이면 반드시 해제)
GPIO 제어: BOOT0=High → RESET Low→High 토글 → STM32가 시스템 부트로더(ROM) 진입
부트로더 응답 확인 (stm32flash가 0x7F sync로 확인, 실패 시 RESET 재토글 재시도)

9단계: 플래싱 실행

stm32flash -w firmware_new.hex -v /dev/serial0 실행
-v 옵션으로 쓰기 후 자동 verify (읽어서 비교)
subprocess 리턴코드와 출력 파싱으로 성공/실패 판정
실패 시 → 제한 횟수(예: 2~3회) 내 재시도. 시스템 부트로더는 ROM이라 몇 번 실패해도 벽돌이 되지 않음 — 이 구조의 최대 장점

10단계: 신펌웨어 기동

BOOT0=Low → RESET 토글 → 신펌웨어로 부팅
시리얼 브리지 재개 준비 (UART 포트 다시 오픈)

11단계: 기동 확인 (RPi 자율 판단 구간)

여기가 앞서 말씀드린 "닭과 달걀" 구간 — STM32가 방금 태어났으므로 판단 주체가 일시적으로 RPi
타임아웃(예: 60초) 내에 STM32로부터 정상 기동 신호 대기
기동 신호 수신 → 성공 확정, 12단계로
타임아웃 → 실패 확정, ROLLBACK(11-1)으로

11-1단계: ROLLBACK (실패 시에만)

보관 중인 구버전 hex로 8~10단계 재수행
구버전 기동 확인
ROLLBACK조차 실패하면 → 재시도 반복 (부트로더는 ROM이니 복구 가능성 항상 유지), 최악의 경우에도 무한 벽돌은 없음

12단계: 결과 전달 및 TUPG

STM32에 최종 결과 통보: 성공(신버전 기동됨) / 실패(구버전으로 원복됨)
TUPG 전송은 STM32가 수행 (규격: 성공 시 PUPG에 명시된 새 통신서버IP로, 실패 시 기존 통신서버IP로)

단, 성공 시 신펌웨어가 새 통신서버IP를 알아야 하므로: PUPG 수신 시점에 STM32가 이 IP를 EEPROM/Flash에 저장해두거나, 12단계에서 RPi가 다시 전달해주는 방식 중 택일 필요


RPi는 브리지 모드로 완전 복귀

13단계: 뒷정리

성공 시: firmware_new.hex → firmware_current.hex로 승격, 기존 current는 firmware_previous.hex로 보관 (다음 ROLLBACK 대비)
실패 시: 다운로드 파일 삭제 또는 실패 이력용 보관
로그 기록 (일시, 버전, 결과, 실패 사유 — 현장 A/S 시 유일한 단서)
